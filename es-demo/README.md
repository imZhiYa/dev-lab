## 🎯 设计哲学：机制验证级，不是 benchmark 级

每个实验只回答一个问题：**机制是否真实发生、量级是否可感**。
- FAST 档：时间尺度缩到"机制可见的最小值"（如可见性轮询 10ms 粒度），一次会话全部 6 实验 ≤10 分钟
- 数据最小化：灌库量只保证信号 ≫ 噪声（如 2~3 万条小文档），测试数据全在容器 overlay，`down -v` 即销毁，零残留
- 参数唯一真源：每个实验的参数固化在对应 Java 类常量与 `scripts/run-exXX.sh`，README 不抄命令
- `SCALE=LONG` 钩子：将来要参数曲线时加长窗口/加档重跑，同一脚本
- 与知识库实验 001-011（curl 级观测）差异化：本模块全部是 **elasticsearch-java 8.15.3 客户端视角**的参数对照

## 📊 实验结果

> 🖥️ **环境**：macOS arm64 宿主 + colima 4C/8G 跨 VM · Zulu 21 · Elasticsearch 8.15.3 × 3 节点（512m 堆/节点，security off） · FAST 档 · 2026-08
> 结果口径：**教学量级（机制验证级）**，跨 VM 只产相对结论，绝对数不外推

| 验证点 | 实测结果 | 机制解读 |
|---|---|---|
| EX-01 批量摊薄 | 单条 363 docs/s → bulk 100=6,377 / 500=11,307 / 1000=16,285 / 5000=18,038 docs/s（**~50 倍**） | 每请求固定成本（HTTP 往返 + 协调 + translog fsync 批处理）被一批文档摊薄；durability=request 下单条写的 fsync 无法摊薄（es-01 写路径固定成本清单） |
| EX-02 可见性一拍 | 默认 refresh=1s：15 轮可见延迟 P50=989ms（min 827 / max 1007） | 写 ACK ≠ 可搜：可搜要等 refresh 把 buffer 变成新 segment，写入落在 1s 拍内随机位置 |
| EX-02 不可见≠没写入 | refresh_interval=-1：写 5 条立即搜=0，sleep 1.5s 后搜=0，手动 refresh 后=5 | 关掉自动 refresh 后"搜不到"持续存在——NRT 的"近"实时就是这一拍（es-01，衔接实验 001） |
| EX-03 副本复制代价 | replicas=0→13,639 vs 1→13,131 docs/s（**-3.7%**，P50 29.9→35.0ms） | 副本是每次写都走的第二条完整链路；本拓扑（colima 单 VM 内 loopback）网络成本极小，代价被低估——跨机网络才是主战场（拓扑边界，见下） |
| EX-04 深分页候选放大 | from=0→9ms / 1000→20ms / 5000→14ms / 9000→18ms（候选 30→27,030，**900 倍**）；from+size=10001 → HTTP 400 拒绝 | 候选数线性放大 900 倍只换来 ~2x 延迟：12k doc 量级下归并成本被页缓存吸收；10000 窗口是资源墙不是性能墙，直接拒绝 |
| EX-04 search_after 平稳 | 每页 1000 翻完 12,000：页延迟 min 18.4 / 中位 27.0 / max 52.4ms，全程无深页尖刺 | 游标把"绝对深度"换成恒定 shards×size 候选——代价是只能顺序翻（es-03，衔接实验 008） |
| EX-05 filter vs query | 同一 match：must 首次 83.92ms vs filter 10.62ms（**~8x**）；重复中位 1ms vs 0ms（took 分辨率 1ms） | filter 上下文跳过 BM25 算分与评分归一；"要不要相关度排序"是写查询的第一问（es-03） |
| EX-05 query cache 边界 | query_cache：hit=0 miss=301 cached=0 | 2 万文档未触发——query cache 是段级缓存，段要足够大才进入候选，FAST 档量级不够，属机制边界而非异常 |
| EX-06 cardinality 精度 | 真实基数 4,988：threshold=100→4,802（误差 3.73%）/ 3,000→4,974（0.28%）/ 40,000→4,988（0.00%）；terms 精确基准 18ms vs cardinality 2-4ms | HLL++ 用精度换内存：阈值低于真实基数时按失真率估计，高于时近精确；"量级 vs 精确对账"选型（es-03 / es-07） |

### 实验过程中发现的真实机制（比表格更有价值）

- **EX-03 副本代价在单 VM 拓扑下几乎隐身**：原以为 replicas=1 会显著拖慢写入，实测仅 -3.7%——因为 colima 单 VM 内三节点走 loopback，"网络转发"这一最大成本项被压到接近零。这恰是拓扑边界证据：副本代价的主战场是跨机网络 + 副本端 fsync，生产跨机部署才可见全貌（对照 mq-demo EX-01 的"单副本 ISR=1 测不到 acks 代价"——同构教训）。
- **EX-04 候选数 900 倍只换来 2 倍延迟**：from=0→9000 候选数放大 900 倍，延迟只从 9ms→18ms——12k 文档全在页缓存里，协调端归并 2.7 万个"轻候选"（doc value 排序键）并不贵。深分页真正的痛在 from+size 更大、字段 fetch 更重时才爆发；但 10000 窗口拒绝与分位数抖动（5000 档中位反而低于 1000 档，5 轮教学量级噪声）是实测实录，如实记录。
- **EX-02 的"不可见"能一直保持**：refresh_interval=-1 下 sleep 1.5s 后依然 0 命中——很多人直觉"等一会儿总会出现"，实测证明不 refresh 就永远不出现，"可见性由 refresh 事件驱动而非时间驱动"。
- **EX-05 的 took 分辨率只有 1ms**：filter 重复中位显示 0.00ms 是服务端 took 向下取整的结果，不是"零成本"；比较应看首次 8x 差异与 P99，重复档两上下文都已进页缓存热路径。
- **EX-06 真实基数本身是随机数碰撞的结果**：30,000 次 nextInt(5000) 的期望 distinct ≈ 4,988（生日碰撞），实测精确基数恰为 4,988——terms 精确基准先自证了随机数与 ES 双方都"没说谎"，HLL 三档误差才有可信的分母。

## 🌐 测试边界声明

**本模块数据不能断言**（也请勿这样引用）：
- 不能据此宣称 ES 的绝对吞吐/延迟上限（跨 VM 网络 + 512m 小堆 ≠ 生产）
- 不能外推集群规模下的复制延迟、深度调优参数曲线、真实业务基数下的 HLL 误差
- 结论形态是"机制发生了 + 相对差异方向"，参数敏感度的绝对值需 LONG 档与生产复核
